## [0.1.0] — 2026-10-10

First tagged release. The template has declared 0.1.0 in `project()` since its first commit; this
tag names a state of the tree rather than introducing new work, so the entries below describe what
the release contains, not what changed since a previous tag — except the move to CNA 0.1.0 and its
14 renderers, which is new.

### Added

- **A starter CNA game in C11** on CNA's native C binding: `HelloGame`, a game loop with texture
  loading, 2D and capability-gated 3D drawing, Android glue, and a `--smoke-test` mode. Every
  important CNA failure is returned through the game callback, so a failed frame fails the
  process and CTest; `--simulate-draw-failure` proves that path deliberately, and
  `tools/verify_ctest_contract.py` pins the CTest contract (exactly two tests, exit status 86).
- **CNA's renderer set as data**: `cmake/renderers.json` carries the template-side metadata for
  exactly CNA's **14** public renderers; `tools/gen_renderer_files.py` cross-checks it against
  CNA's `CNA_RENDERER_PUBLIC_IDENTITIES` and generates `CMakePresets.json` and
  `docs/renderers.md`; `cmake/CnaRenderers.cmake` refuses an unknown or platform-invalid renderer
  at configure time with an explanation.
- **Reproducible dependency pins**: `dependencies.lock` names the exact sibling commits,
  `tools/dependency_pins.py` parses them for the setup instructions and CI, and
  `cmake/CnaDependencyPin.cmake` verifies every consumed checkout at configure time.
- **Release identity**: `CnaTemplate/Version.h`, generated by `cmake/CnaTemplateVersion.cmake`
  from `project(CnaTemplate VERSION ...)` and `CNA_TEMPLATE_VERSION_PRERELEASE`, with
  `cna_template_version_string()` and the `CNA_TEMPLATE_VERSION_*` macros; the game's banner
  prints it.
- **Required sibling releases**: `cmake/CnaTemplateDependencies.cmake` reads each sibling's
  generated `Version.hpp` after CNA is added and refuses an incompatible checkout (see
  *Dependencies*); `-DCNA_TEMPLATE_CHECK_DEPENDENCY_VERSIONS=OFF` downgrades it to a warning.
- The template's own Python checks under `test/`, a CI workflow (`.github/workflows/ci.yml`) that
  builds and tests the pinned `headless` configuration and validates the Android Gradle
  configuration, and `docs/releasing.md`.

### Changed

- **Moved to CNA 0.1.0 and its 14 renderers.** The manifest, the generated presets and
  `docs/renderers.md`, the Gradle renderer dependency logic and the template's own tests dropped
  the 36 renderers CNA retired (`BGFX`, `MAGNUM`, `SKIA`, `CANVAS`, `GDI`, `DIRECTX12`,
  `OPENGLES2`, `WEBGL1`, `FREEDIRECT`, …). Selecting one is now a configure error naming it, as in
  CNA. The `free-direct` sibling pin went with `FREEDIRECT`, and the Emscripten `CANVAS`
  compatibility overlay (CNA-8) was removed; `docs/compatibility.md` marks it obsolete.
- The generator and `cmake/CnaRenderers.cmake` read CNA's renderer list from
  `cmake/RendererIdentities.cmake` (`CNA_RENDERER_PUBLIC_IDENTITIES`), where current CNA keeps it,
  with the old `STRINGS` line of `RendererSelection.cmake` as a fallback for older checkouts.
- The manifest marks the web as an *experimental* platform of `WEBGPU`, as CNA's own web CI
  builds `WEBGL2;WEBGPU` together under Emscripten through the Dawn port.
- The dependency pins name the `libcna` organization, where the repositories live
  (`openeggbert/...` redirects there).
- **The browser build drives its own loop.** CNA's C API is linked without Asyncify by design,
  so a page cannot block in `cna_game_run()`; under Emscripten `Program.c` now advances the run
  one frame per animation frame with `cna_game_run_frame_ext()` and exits with the same status
  contract as the native run. The executable inherits CNA's JS exception ABI instead of forcing
  `-fwasm-exceptions`, which the current CNA refuses at link time.

requires the versions. A checkout at the required version or a later patch release of the same
minor line passes the version check; the pin check still wants the exact commit unless
`-DCNA_ALLOW_UNPINNED=ON`.

### Verification

- `tools/gen_renderer_files.py --check`: the manifest matches CNA 0.1.0's 14 canonical renderers
  and the generated presets and docs are up to date; `python3 -m unittest discover -s test`:
  **59/59**.
- The pinned `headless` preset (`build-headless/`, Debug): configure prints
  `cna-c-template: version 0.1.0`, `CNA matches dependencies.lock` and accepts CNA 0.1.0 and
  sharp-runtime 0.1.0; 0 errors; `tools/verify_ctest_contract.py` verifies the two-test contract
  and both pass (the smoke run and the deliberate draw failure with exit status 86).
- Linux multi-renderer build (`build/`, Release, `OPENGLES3` default plus `OPENGL33`, `VULKAN`,
  `WEBGPU`, `SDL_GPU`, `FNA3D`, `SDL_RENDERER`, `SOFTWARE`, `HEADLESS`, `STUB`): all four
  siblings accepted, 1,053 steps, 0 errors (28 CNA-side warnings); the contract verifies and both
  tests pass on CNA's private GPU runner; shown on the real desktop with `OPENGLES3`, `VULKAN`
  and `SDL_RENDERER`, the banner reading `cna-c-template 0.1.0 (CNA C ABI 0.46.0)`.
- Web build (Emscripten 6.0.9, `build-web-webgl2/`, Release, `WEBGL2` default + `WEBGPU`):
  configure accepts all four siblings and warns, as designed, that the web is an experimental
  `WEBGPU` platform; 0 errors; `HelloGame.html/.js/.wasm/.data` produced (wasm 5.9 MB) with both
  renderer identities compiled in. The browser run was not automated (no browser on this host).
- Verified on Debian GNU/Linux 13 with GCC 14.2.0, CMake 3.31.6, Ninja, Mesa 25.0.7 and
  Emscripten 6.0.9. Windows (MinGW), macOS and Android were not re-verified at this pin.
